# 运行与成本保护

本文面向自行部署 PlayWithAnyone 的运营者。代码提供资源护栏、管理接口和有界工具；每个部署仍需配置自己的资源、密钥、额度与验证记录。实际安装和部署入口见 [README](../README.md)，保护机制见 [成本与运行安全补充规范](PlayWithAnyone_Cost_and_Safety_Addendum_v1.0.md)。

## 免费优先与能力状态

先用适用的免费服务和小额度配置验证首款游戏。仓库中的示例数值不是开销授权；流量增长不会授权脚本升级套餐、购买实例或自动扩大限额。

| 能力 | 当前实现边界 |
| --- | --- |
| 四子棋回合制 | 使用 `hibernated-turn`；WebSocket 事件触发处理，Alarm 保存期限，无服务器保活循环 |
| 房间内核 | `RoomRuntimeCore` 通过连接、调度、检查点、结算及规则加载端口连接宿主；纯 Node 测试不代表已部署其他宿主 |
| 控制面 | 匹配、会话、D1、R2、发布与资源护栏保留在 Cloudflare |
| P2P、实时 Tick、TURN、VPS | 未启用；预留接口和配置位置不代表可用服务，相关类别保持禁用和零额度 |
| 独立 watchdog 与通知 | 工具已有实现，默认不安装定时任务、不发送通知；启用前须单独配置和验证 |

需区分三种限制：

- **供应商硬额度**决定某项服务超限后是否拒绝操作，作用范围以实际套餐为准。
- **应用配额**限制允许创建和处理的工作，是资源计数，不能直接当作供应商实际用量。
- **运营预算与账单**覆盖实际费用，包括固定费、按量费、持续存储及其他已登记项目；告警不等于美元硬封顶。

免费额度通常有共享范围，不能给每个游戏或环境各复制一份。启用 R2 等按量服务前，单独检查超额规则。官方依据：[Workers](https://developers.cloudflare.com/workers/platform/pricing/)、[Durable Objects](https://developers.cloudflare.com/durable-objects/platform/pricing/)、[D1](https://developers.cloudflare.com/d1/platform/pricing/)、[R2](https://developers.cloudflare.com/r2/pricing/)。部署时重新核对套餐，不依赖文档里的历史价格。

## 配置副本与密钥

按 README 的配置步骤，从示例建立自己的部署副本，绑定账号资源、域名、构建和应用保护周期。示例保留占位值时停止部署；未启用能力保持未指定或禁用，不用测试参数补成生产配置。

账号、数据库或区域标识不等于凭据，但部署副本应与公开示例分开，避免误操作他人的环境。具体预算授权、通知接收信息和原始云日志也由运营者私有保存。公开源码中的 `server-private` 表示运行时资源访问边界；游戏规则源代码可以公开，部署后仍只由受信任宿主加载。

密钥放在部署平台的 Secrets 或项目外、权限受限的环境文件中，不写入源码、命令参数、发布包或日志。至少分离以下权限：

| 用途 | 权限边界 |
| --- | --- |
| 发布与迁移 | 仅用于明确的管理员操作，不交给定时巡检 |
| 指标采集 | 对所需指标只读，无发布或恢复权限 |
| 停止 | 只允许指定环境的保护动作，无删除数据权限 |
| 恢复 | 独立于停止凭据，要求原因、配置版本和验证记录 |
| 通知 | 只允许已配置渠道，不复用广泛权限的部署令牌 |

换配置、换逻辑池名或进入新周期均不能解除事故锁。迁移匹配池时保留记账 owner，或按可审计的一次性流程转移已有用量。

## 日常查看

普通 D1 读取采用最多 512 行、最长 60 秒的有限预付租约。读取链路不会逐条写成本账本，每次仍用主键查询复核持久事故锁；业务写入具有独立的预扣与原子边界。租约未用完的额度和供应商实际读写分别统计，进程重建不自动退回不确定用量。

管理状态每页最多观察 8 个房间。读取方须有界地跟随 `observation.nextCursor`，校验同一次扫描及保护版本，直到 `observation.complete`；不能把第一页、部分结果或未知房间当成全部停止。最后一页给出累计计数，各页计数不可相加。

使用现有只读状态工具或 watchdog 的 `collect` / `plan` 模式查看用量与预演阈值。调用数、响应体和总时长必须有界；权限不足、空结果、截断、滞后分别记录。数据不可取得时标记未知，不能当作零或无限重试。

配额调整前为对应游戏建立 [资源画像](RESOURCE_PROFILING.md)。并发、单位时间创建量、日累计和周期累计分别检查；降低并发不能替代数据库、消息、上传和生命周期限制。

## 手动发布与保护

发布由运营者明确执行。先检查目标环境与配置，生成并核对不可变产物、摘要和许可文件，再执行指定目标的发布；公开 GitHub 仓库不会自动授权更新线上站点。

发布 journal 保留每次操作和回执。结果不确定时先核对云状态，不能通过删掉 journal、换账本 key 或盲目重发绕过限额。示例脚本不应自动升级套餐、开放禁用类别或运行未配置的后台巡检。

保护状态按 `NORMAL`、`WARNING`、`DRAINING`、`BLOCKED` 持久保存。停止动作拒绝新活动，并通过持久的有界分批任务关闭已有连接和不必要工作；任务待执行或传播失败时不得宣称全部停止。等待匹配的连接也纳入观察与关闭。

入口阻断只保护其覆盖范围，不能代替关闭已经建立的 WebSocket。停服不删除数据库、对象或检查点；必要收尾受有限操作量和时间约束，不能伪造胜负或无限重试。

恢复需要独立认证、事故原因、配置版本及同环境的验证记录。先确认原风险已消除，再观察 D1、匹配池与房间的恢复结果；日切换、重启和重新部署不能自动解锁。

## 可选巡检与通知

启用独立 watchdog 前，登记运行位置、共享故障域、指标权限、延迟上界、停止范围和失联保护，并验证停止与恢复。只有代码存在或脚本能启动，不算巡检已经运行。

通知默认不启用。运营者自行选定接收渠道、最小权限凭据和有限发送预算，显式发送测试后分别记录提供商接受与实际送达。通知失败不阻止保护，网络结果不明保留未确认状态，不盲目重发。

正式运行前逐项确认：已启用服务与入口有清单；当前额度和保护周期有效；密钥权限独立；管理观察完整；旧连接和后台任务可停止；必要通知已验证；持续费用和未知项已如实登记。某项能力未启用时，不要求为其提前购买服务。
