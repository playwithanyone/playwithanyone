# 每款游戏的资源画像

使用 `scripts/resource-profile/` 的有界工作负载和采集工具，为每款游戏选择配额。
配置位于 `configs/resource-profiles/`；权限和运行要求见 [运营说明](OPERATIONS.md)。

## 测量场景

固定游戏、构建摘要、规则、同步模式和宿主。先限制玩家、房间、并发、请求、消息、
字节、总时长和采集调用数，为终局、会话撤销和连接关闭预留额度。

覆盖建房与加载、双方准备、典型完整对局、较重合法对局、保持连接的静默窗口、
恢复首步、断线/超时、终局和清理。静默窗内不发送轮询或应用心跳，不查询房间或管理接口；
思考期限改变时，前后空闲窗口分别记录。

## 指标

| 数据 | 记录内容 |
| --- | --- |
| 客户端 | HTTP/WS 数量、应用字节、合法输入、双端状态延迟、错误和清理结果 |
| 应用 | 并发占用、创建量、读取预扣、消息与字节预算 |
| 供应商 | Worker 请求/CPU、DO 活动量/CPU/SQLite 行数、D1 实际读写、R2 操作与保存字节 |

DO SQLite 与 D1 分开记录。查询返回行数不等于扫描量，写入行数不等于保存字节。
连接或房间的挂钟寿命不等于计费活动时间；DO duration 使用官方 GB-s 口径。

每个窗口保留 UTC 起止、采集时间、统计桶、指标来源、采样和完整性状态。
失败、缺样、权限不足、截断和滞后不补零；重采与重叠窗口不相加。
共享数据库、匹配池和后台流量单列，缺少归因时不全部摊到棋局。

## 推导限额

```text
本游戏可用额度 = 共享额度 − 其他用量 − 后台开销 − 未知项与保护余量
候选日吞吐量 = 本游戏可用额度 / 保守的代表性完整局消耗
```

用较重合法场景估计各类资源，检查最先触线的一项。
并发控制瞬时占用，日/周期限额控制周转；小规模测试不能认证更高并发容量。
游戏或宿主变化后重测相应场景，不将四子棋结果直接用于 P2P 或持续 Tick。

保留版本、硬预算、实际工作量、指标单位、数据质量、体验结果、异常和未覆盖范围。
收尾确认房间终局、测试凭据撤销、连接关闭及本次任务清理。
