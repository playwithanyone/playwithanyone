### 1.2 必须遵守的范围

1. 所有游戏使用平台 SDK、游戏模块接口和平台协议。
2. 不保留第三方游戏后端、账号、房间或私有联机协议的兼容适配层。引擎和语言绑定只能调用同一套 SDK。
3. 实现并验证全部五种同步模式：`server-turn`、`deterministic-lockstep`、`duel-rollback`、`peer-host-snapshot`、`server-snapshot`。
4. 核心设施为 Workers、Durable Objects、D1、R2、TURN。高频运行实例及专用网络端点只供需要它们的同步模式使用。
5. 不实现多设备输入合并、`continuationId` 或控制授权失效后的独立续玩机制。
6. 未绑定的产品策略保持未指定。不得用示例值、测试配置或异常处理分支设置生产默认行为。
7. 测试游戏不自动进入正式游戏目录。首发数量、具体游戏、品牌、生产域名和开放时间由独立配置确定。
8. 只执行任务范围内的操作。购买资源、修改生产环境或公开发布，需要当前任务已包含相应授权。

### 1.3 术语

| 术语 | 定义 |
| --- | --- |
| Profile | 一种明确规定规则执行者、同步方式和运行环境的配置；简称同步模式 |
| 权威 | 获平台授权、能够推进规则或确定输入顺序的执行者 |
| 投影 | 根据观看者权限，从规则状态生成的可见数据 |
| Tick | 模拟中的一个固定时间步 |
| 连续 ACK 位置 | 指定接收上下文内，`nextExpected` 之前的序号或 tick 已连续收到；不等于已应用或已持久提交 |
| 检查点 | 用于恢复的状态及相关版本、日志位置和确认记录；内容按同步模式确定 |
| COMMITTED | 已达到该同步模式规定的提交条件，且具有相应的可查询、可恢复依据 |
| outbox | 与业务状态一起持久保存的待发送记录；发送失败后按原标识重试 |
| tombstone | 持久关闭记录；用于拒绝迟到消息重新创建已关闭的分配或对象 |
| 测试夹具 | 测试专用的游戏、数据、策略配置或故障条件；必须与生产配置分开 |

## 3. 配置规则

### 3.1 配置分类

| 类别 | 示例 | 规则 |
| --- | --- | --- |
| 协议常量 | 32 字节帧头、端序、opcode、字段范围 | 按规范实现 |
| 工程参数 | 部署绑定、重试次数、历史容量、采样频率 | 明确数值、来源、作用范围和限制 |
| 产品策略 | 排队期限、扩区、断线处置、旁观开放 | 使用已绑定的版本；未指定时报告缺项 |
| 测试配置 | 测试频率、测试等待时间、故障时序 | 标记为测试用途；生产不得回退使用 |

工程超时、缓存容量或资源限额不得自动决定判负、扩区、补位或账号并发限制。

### 3.2 策略解析

实现规范 §2.2 的 `PolicyBinding` 与 `PolicyResolution<T>`：

1. 校验所属能力要求的字段、类型、取值范围和版本。
2. 缺少必要配置时，解析器返回 `UNSPECIFIED` 和 `requiredKeys`。
3. 具体行为入口在执行前检查解析结果；缺少该行为必需的策略时返回 `POLICY_REQUIRED`。
4. 不把未指定值转换为 `false`、`null`、空列表、无限制或示例数值。
5. 仅检查当前行为需要的策略，不要求配置尚未采用的能力。
6. 在进入相关行为前固定所用策略版本。修改开发配置不得改变已经固定的对局策略。
7. 不建立用于穷举所有假想产品选择的通用策略引擎。

### 3.3 待绑定的产品策略

以下事项通过显式策略处理：游客参与条件、账号并行活动数量、房间管理权限、开局条件、匹配等待与扩区、断线等待和判负、补位与接管、网络隐私默认、赛后行为、旁观与中途加入、回放访问与保存、排名奖励、生产费用和体验阈值。

只实现规范已经定义的能力和接口。投票、机器人接管等未选定流程保持配置或接口边界，不为测试预建完整产品机制。

## 4. P0：环境准备

### 4.1 依赖检查

| 环境或材料 | 首次需要的阶段 | 缺失时的处理 |
| --- | --- | --- |
| 架构规范、固定工具版本、用例清单 | P1 | 记录缺项；不猜测协议 |
| 多 origin 的可信 HTTPS、证书和域名解析 | P2 | 相关浏览器测试记为 BLOCKED |
| 本地实际 Workers/DO/D1 运行和存储环境 | P2/P3 | 相关组件测试记为 BLOCKED |
| Cloudflare 测试部署、D1、R2 和受控域名 | P2/P3 的云测试 | 本地与云测试分别记录 |
| TURN 账号、服务端密钥和短期凭证签发 | P4 | TURN 与 relay-only 测试记为 BLOCKED |
| 高频运行实例和授权入口 | P5 的 server-snapshot | 该模式正常运行测试记为 BLOCKED |
| 声明支持的实体设备与公网环境 | P6 | 对应设备和网络测试记为 BLOCKED |
| 生产策略、目录和预算阈值 | 相关生产行为开放前 | 列入生产就绪报告的缺项 |

环境缺失只阻塞依赖该环境的任务。纯协议测试不依赖付费云环境。

### 4.2 域名、证书和资源

1. 主站与不可信游戏必须使用不同的可注册域（eTLD+1）。
2. 每个游戏构建使用独立 origin，主机标签为 `b-<digest-base32>`。完整 SHA-256 转为 52 个无填充小写 base32 字符，加 `b-` 后为 54 字符。
3. 公开资源使用独立 origin，不承载认证、登录回调、写入 API、任意重定向或任意 URL 代理。
4. 公开资源 origin 可以位于游戏侧可注册域的独立子域。资源请求、Cookie、CORS、CORP 和缓存仍须满足规范 §11。
5. 分别检查 DNS、TLS 证书、Worker 路由和构建注册表。每个构建 Host 只能映射到对应的不可变构建。
6. Cloudflare Universal SSL 的覆盖范围按实际域接入方式检查。Workers Custom Domains 不支持泛匹配；泛构建子域使用符合要求的 Workers Routes 配置。[R1][R2][R3]
7. 公开构建资源与私有检查点使用隔离的存储和访问路径。私有对象不得进入公开资源缓存。
8. TURN 长期密钥仅保存在服务端。浏览器可信 Runtime 使用短期凭证。[R4]

### 4.3 本地浏览器环境

1. 使用可信的多域 HTTPS 环境运行跨站 Cookie、iframe、Worker 和线程测试。
2. 本地解析必须覆盖实际构建 Host。使用精确 hosts 记录或本地 DNS；hosts 不支持通配。[R5]
3. 证书、解析和代理分别配置。mkcert 与 Caddy 可以作为工具选择。
4. 安全验收不得全局忽略 TLS 错误，不得关闭 CSP、来源检查或浏览器隔离。
5. 报告记录浏览器引擎、版本、操作系统、设备和网络。
6. Playwright 的设备模拟与实体设备测试分别记录。Playwright WebKit 不计为 Apple 品牌 Safari 的实体设备测试。[R6][R7]

## 5. 测试与结果记录

### 5.1 测试环境分类

| 标记 | 环境 | 记录范围 |
| --- | --- | --- |
| L0 | 纯算法、实际 codec、固定数据、参考模型、模拟时钟或模拟通道 | 字节、边界、算法和状态变化 |
| L1 | 实际应用模块与本地或集成运行环境，使用实际授权、路由和存储接口 | 组件协作、事务、重试和恢复 |
| L2 | 实际浏览器、HTTPS、WS/RTC、引擎导出产物和应用调用链 | 浏览器加载、隔离、网络绑定和游戏行为 |
| L3 | 实际 Cloudflare、TURN、条件运行实例，以及指定设备和公网环境 | 部署、云服务、设备、网络、性能与费用 |

模拟时钟、模拟通道、测试替身必须在报告中注明。L0 结果不得计作 L1、L2 或 L3 结果。本地存储测试不得计作实际云存储测试。

### 5.2 实现状态

| 状态 | 含义 |
| --- | --- |
| `NOT_IMPLEMENTED` | 尚未实现 |
| `CONTRACT_ONLY` | 只有接口或数据结构 |
| `IMPLEMENTED_UNVERIFIED` | 已有实现，所需测试尚未完成 |
| `IMPLEMENTED_AND_VERIFIED` | 已实现且规定的测试通过 |

### 5.3 测试状态

| 状态 | 含义 |
| --- | --- |
| `PASS` | 在要求的环境中实际执行并满足所有断言 |
| `FAIL` | 已执行，结果不符合要求 |
| `NOT_RUN` | 尚未执行 |
| `BLOCKED` | 缺少明确的环境、凭证、设备或其他依赖 |
| `N/A` | 根据能力声明和适用条件，该项不适用 |

实现状态和测试状态分别记录。`N/A` 必须给出适用依据，不计作 `PASS`。缺环境使用 `BLOCKED`；未实现的目标能力不得改记为 `N/A`。

一个源用例可以拆成多个子测试。全部适用且必需的子测试通过后，源用例才记为 `PASS`。P02 至少分为：server-turn 无 Tick 池运行、rollback 无 Tick 池运行、server-snapshot 缺必要承载时拒绝启用。

### 5.4 测试编写要求

1. V1/V2/V3 使用规范原始字节作为预期值，不由被测编码器生成。
2. 关键状态变化使用独立参考模型、独立预期值或明确不变量检查。
3. 拒绝请求时，检查未转发、未修改他人状态、未推进他人确认位置。
4. 重投递和重试测试检查实际规则应用次数、数据库记录和统计增量。
5. 用例清单与实际执行集合对账。记录缺项、skip、xfail、`.only`、空测试、筛选范围和重试。
6. 保留首次失败和后续重试结果。未解释的不稳定失败不得报告为完成。
7. 故障注入记录发生位置与时序，包括发送队列、实际连接、接收实例、DO 生命周期、事务提交和外部存储。
8. 对已提交状态，分别测试提交前崩溃、提交后崩溃、回复丢失和重复通知。
9. DO 恢复测试必须清除实例内存并保留持久数据。使用相应测试运行时的实例中止或逐出机制，区别于清空数据库；实际云生命周期单独验证。[R8]
10. 每项任务运行相关新增测试和受影响的既有测试。测试范围按修改影响确定。

### 5.5 每条结果的必填字段

规范版本与摘要、计划版本、提交 SHA、源章节、用例与子测试编号、L0—L3 环境类别、Profile、能力声明、策略和测试数据摘要、运行命令、工具与环境版本、故障 seed 和时序、预期结果、实际结果、状态、重试与跳过原因、日志或结果文件路径。

### 6.2 P1：协议与纯逻辑

**实现要求：**

1. 实现 `PolicyBinding`、`PolicyResolution<T>` 和所属能力的字段校验，遵守第 3 节。
2. 实现规范 §9.2–9.7 的 32 字节小端帧头。校验 `magic = 0x5750`、`MAX_FRAME_BYTES = 16384`、保留位、长度、opcode、上下文和序号范围。帧载荷最多 16352 字节，`MAX_GAP_RANGES = 32`。
3. 使用 BigInt 或两个 u32 无精度损失地读写 u64 `contextTag`。处理 `0xffffffff` 哨兵和序号耗尽，不允许自然回绕。
4. 实现 `COMMAND / INPUT_BATCH / STATE / BULK_CHUNK / ACK / GAP_REQUEST / CLOCK_PING / CLOCK_PONG` 载荷和规范定义的控制 JSON 消息。
5. 控制 JSON 只接受定义的消息类型和字段。嵌套深度最多 8，单数组最多 64 项，普通字符串最多 4096 个 UTF-8 字节，SDP 字符串最多 32768 字节，完整控制消息最多 65536 字节。发送大小还受已授权描述符和底层协商上限约束，取其中最小值。
6. 发送历史和输入历史按绝对序号或 tick 查找。缓存满时返回规范规定的背压或历史耗尽结果，不覆盖未确认内容。
7. 实现连续 ACK、缺口请求、迟到缺口处理、补发判定和恢复信号。
8. 实现四时间戳 RTT/时钟偏移估算；拒绝不属于当前时钟域的消息、非法数值和未知探针。
9. 建立用例清单、独立状态模型和测试结果输出。

**完成条件：**

- 规范 §9.8 的 V1、V2、V3 逐字节一致，长度分别为 36、43、52 字节。
- §9.9 十五类场景的 L0 子测试全部完成。
- 需要实际授权、WS/RTC 或迁移的子测试登记到后续阶段，不报告为已完成。
- 本阶段不要求 DOM、DO 或 WebRTC 连接层实现。

### 6.3 P2：发布、沙盒与 SDK 通信

**实现要求：**

1. 校验 `client / public-simulation / server-private / assets` 依赖。公开包、source map、视图和公开恢复数据不得包含私有规则状态。
2. 按规范 §12 生成不可变发布清单，使用 RFC 8785 JCS 和完整 SHA-256 计算 `gameBuildId`。构建 Host 从该身份派生，不把派生 URL 递归纳入自身摘要。
3. 实现资源注册表和受控加载路线。分别设置 Shell、iframe、普通 Worker 和资源响应所需的 CSP、COOP、COEP、CORP、Permissions-Policy。
4. 实现最小实际会话、`__Host-pwa_session` Cookie、API 来源/CSRF 检查和会话撤销。测试身份不决定生产登录要求或登录提供商。
5. 实现 `BOOT_CHALLENGE`，使用至少 128 位安全随机 nonce。验证准确的 origin、source、nonce、实例、构建和协议版本，建立受限 MessagePort 并绑定 `PresentationBinding`。

### 6.4 P3：单池匹配、Room 与 server-turn

**实现要求：**

1. 实现 MatchPoolDO 的队列、候选筛选、取消、预留和分配。

### 6.5 P4：实际传输、锁步与回滚

传输、deterministic-lockstep 和 duel-rollback 分别实现并验收。

**传输要求：**

1. 实现平台信令、DTLS SHA-256 指纹规范化和 `PathAuthorization`。指纹规范形式为 64 个小写十六进制字符。远端指纹与平台授权不一致时拒绝连接绑定。
2. 实现 WSS 和规范规定的两个 DataChannel：`pwa.reliable` 使用 `id: 0, ordered: true`；`pwa.fast` 使用 `id: 1, ordered: false, maxRetransmits: 0`。通道协商方式按规范 §9.3.1。
3. 使用实际 TURN 服务验证短期凭证与 relay-only。持有 TURN 凭证但没有游戏授权时，仍拒绝游戏数据。
4. 实现 `PATH_BIND / PATH_READY`、实际接收器安装确认、连续接收位置对齐、缺口补传和失效路径处理。
5. WS/RTC 切换不写控制面路由 COMMIT，不改变 `matchId` 或 `authorityEpoch`。
6. 路径选择满足同步模式、隐私设置、实际就绪状态和路径质量要求；不固定所有对局的切换时刻。
7. 在 T08 前完成接收实例重建所需的状态与日志恢复。重连从实际恢复点重新确认，不继承丢失状态对应的旧 ACK。
8. 验证旧接收端的权限撤销或到期。控制授权失效时遵守规范 §8.5，不创建新的独立权威或续玩身份。
9. 历史不足时发出规范规定的恢复或不可恢复结果，不生成虚假确认。

**deterministic-lockstep 要求：**

1. 明确输入排序者及其平台授权。
2. 固定输入集合、输入次序、数值规则和随机源。
3. 在声明支持的浏览器与运行时中，对相同初始状态和输入得到相同状态摘要。
4. 必要输入缺失时，不越过该模式规定的确认位置。
5. 实现状态摘要检查、不同步检测和恢复或失败处理。

**duel-rollback 要求：**

1. 支持两名主动玩家交换输入，固定时间步与渲染分离。
2. 实现输入历史、状态快照、预测、确认、回滚和重新计算。
3. 使用稳定 `effectId` 确认或撤销表现效果。
4. 永久奖励和其他不可撤销副作用只从已提交事实产生，并按稳定标识去重。
5. 测试游戏的频率、回滚窗口和网络条件写入显式测试配置。

**完成条件：**

- 完成 A02–A04、T01–T08、R03、SEC-14/15、C01 的规定子测试。
- 完成 P02 的 rollback 无 Tick 池运行测试。

### 6.6 P5：快照同步、迁移和跨池转移

**完成条件：**
